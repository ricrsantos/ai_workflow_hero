## Telegram reply settings

The project-local `hero.json` Telegram configuration supports `auto_report_minutes` and `always_send`. `always_send` defaults to `false`, preserving Telegram replies only for Telegram-originated prompts; when enabled, the TUI forwards the completed final response of local harness turns through the paired Telegram connection as well. Settings exposes both controls in the Telegram section.

## Harness transport reconnect

Quit/restart while streaming uses two-phase cancel: `pendingQuitAfterInterrupt` waits for `streamCancelDoneMsg`, then synchronous session interrupt persistence before `tea.Quit`. Interrupted-session recovery calls optional `harness.LiveStreamAttacher` (OpenCode: resume + SSE attach); other harnesses with a still-running native turn show unsupported copy instead of `ResumeSession` polling.

Mid-turn harness disconnects emit `⚠ connection closed; reconnecting…` / `✓ harness reconnected` via shared `harness` stream deltas. Codex restarts `app-server` and resumes the thread; OpenCode keeps SSE/serve recovery and surfaces the same copy; Cursor retries process/transport failures with the same `SessionID`. The TUI health path never auto-cancels; disconnect recovery stays inside adapter Execute.

## Implemented Features

- **Multi-agent Implementation contract (ADR-075 follow-up)**: Every implementation task has exactly one canonical owner (`backend_agent`, `frontend_agent`, or `generic_agent`). Ownerless legacy tasks are routable only when exactly one implementation agent is active; missing or invalid ownership fails closed with multiple agents. The scheduler prepares per-agent prompts with the linked task file, exact IDs, dependencies, acceptance criteria, and verification commands. Reports validate stage/agent identity and require `tasks_completed` plus `tasks_remaining` to be the disjoint union of the assigned IDs. The TUI/runtime scheduler is the only checkbox writer and atomically marks IDs only after report/evidence validation. Selective waves redispatch only agents with remaining IDs. Claude prompt routing resolves the projected `.claude/agents/<agent>.md`. Assignment audits persist normalized, ordered `task_ids` (mixed `task-*`/`find-*`) in conversation JSON; raw agent results keep exact `body` with `result_validated=false`, and scheduler-validated results add normalized `tasks_completed`/`tasks_remaining` with `result_validated=true` via `cycle.StageAgentAuditBody`.
